## 2. قرارات معمارية

كل قرار أدناه مُعتمد للتخطيط. تغييره يحتاج سبباً مكتوباً لأن الوثائق الأخرى مبنية عليه.

| المعرّف | القرار | البديل المرفوض ولماذا |
|---|---|---|
| D-01 | قاعدة MySQL/MariaDB واحدة. كل جدول تشغيلي للمنشأة يحمل `tenant_id`. عزل إضافي بمفاتيح أجنبية مركبة `(tenant_id, id)`. | قاعدة لكل منشأة: تتجاوز حصة قواعد الاستضافة المشتركة وتصعّب النسخ الاحتياطي والترحيل. |
| D-02 | المفتاح الأساسي `BIGINT UNSIGNED` ترقيم تلقائي. المعرّف العام `public_id CHAR(26)` بصيغة ULID. الواجهات وواجهات البرمجة تعرض ULID فقط. | UUID نصي `CHAR(36)` كمفتاح أساسي: أكبر، وترتيبه عشوائي، فيبطئ الإدخال على الجداول الكبيرة (طلبات، حركات مخزون). |
| D-03 | Monolith معياري داخل Laravel. المجالات تحت `app/Domain/*`. لا Microservices ولا حزم تعدد قواعد. | `stancl/tenancy` بقاعدة لكل مستأجر: يخالف D-01. تقسيم الخدمات: يحتاج عمليات لا تملكها الاستضافة. |
| D-04 | الواجهة: Blade + Livewire + Alpine + Tailwind. Vite يبني الأصول على جهاز المطور. الإنتاج يستقبل ملفات مجمّعة فقط. | Inertia + SPA: نفس قيد البناء المحلي، لكن نقطة البيع وشاشة المطبخ أبسط وأقرب لحدود PHP عند بقاء الحالة على الخادم. Livewire يملك `wire:poll` المناسب للاستضافة المشتركة. |
| D-05 | عند بدء التنفيذ يُثبَّت أحدث إصدار Laravel رئيسي ما زال له 12 شهراً من إصلاحات الأمان، إذا طابق PHP المتاح. | البقاء على إصدار اقترب نهاية دعمه الأمني: مرفوض. |
| D-06 | الجلسات في جدول `sessions`. الكاش ملفات. الطابور جدول `jobs` بسائق `database`. | Redis: غير متاح وممنوع افتراضه. كاش قاعدة البيانات: يضاعف الحمل على MySQL المشتركة. جلسات الملفات: قفل الملف يزعج تزامن الكاشير. |
| D-07 | الاستطلاع القصير لتحديث المطبخ (8 ثوانٍ) ولوحة الطلبات (15 ثانية). | Long polling وWebSocket ذاتي: يحجزان عمال PHP أو يحتاجان عملية دائمة. Pusher/Ably: خدمة مدفوعة، تُؤجل لما بعد إثبات الحاجة. |
| D-08 | الروابط العامة: `https://{platform}/{slug}/menu` و `/{slug}/order` و `/{slug}/reserve`. لوحة المنشأة على نفس النطاق بعد تسجيل الدخول، والمنشأة تُستنتج من المستخدم لا من عنوان يرسله المتصفح. | نطاق فرعي لكل منشأة في الإطلاق: يحتاج Wildcard DNS وشهادة تغطي `*.domain`. يُعاد تقييمه بعد إجابة المزوّد. |
| D-09 | أسماء الخطط لا تُكتب في الشروط. المزايا مفاتيح في جدول `features`. | `if (plan === 'pro')` يتناقض مع إدارة الخطط من لوحة المشرف. |
| D-10 | أسعار وأسماء أصناف الطلب تُنسخ داخل `order_items` و `order_item_options` لحظة التثبيت. الضريبة تُحسب وتُخزَّن كمبلغ، مع نسبة الضريبة المطبقة كنسخة. | الربط الحي بسعر المنتج الحالي يغيّر التاريخ المالي. |
| D-11 | المخزون دفتر حركات `stock_movements` غير قابل للحذف من الواجهة. `branch_stocks.quantity` رصيد مشتق يُحدَّث داخل نفس المعاملة. | تحديث الكمية فقط: لا جرد ولا أثر مراجعة. |

| D-14 | الطباعة الأولى: CSS بعرض 80 مم و `window.print()`. QZ Tray أو ESC/POS خيار لاحق على جهاز الكاشير، بلا متطلبات خادم. | خادم طباعة: غير متوافق مع الاستضافة المشتركة. |

| D-17 | التقارير الثقيلة تُقرأ من `daily_branch_summaries` الذي يملأه المجدول ليلاً. التفاصيل تُستعلم بمدى تاريخ إلزامي. | تجميع حي على جدول الطلبات لكل زيارة تقرير: يضغط MySQL المشتركة. |

## 3. افتراضات مؤقتة

هذه الافتراضات صالحة للتصميم فقط. كل واحدة تسقط إذا ناقضها جواب المزوّد أو قرار المالك.

| المعرّف | الافتراض | إن ثبت العكس |
|---|---|---|
| A-01 | الإنتاج PHP 8.3 أو 8.4 بامتدادات: `pdo_mysql`, `mbstring`, `openssl`, `tokenizer`, `xml`, `ctype`, `json`, `bcmath`, `fileinfo`, `gd`, `curl`, `intl`, `zip`. Argon2id متاح في بناء PHP. | إن غاب `intl` أو `gd` أو `bcmath` أو كان PHP أقدم من 8.3 فالاستضافة غير صالحة لهذا المشروع. |
| A-02 | PHP CLI متاح من Cron في cPanel حتى لو غاب SSH. | بلا CLI لا ترحيل ولا جدولة. هذا شرط إيقاف، لا مخاطرة عادية. |
| A-03 | Cron بدقة دقيقة واحدة على الأقل، والأمر لا يُقتل قبل 60 ثانية. | إن كانت أقل دقة تُزاد فترات الاستطلاع وتُراجع المهام الزمنية. إن مُنع Cron تُرفض الاستضافة. |
| A-04 | قاعدة واحدة على الأقل، مستخدم بصلاحيات DDL داخلها (CREATE/ALTER/INDEX/FOREIGN KEY)، ومحرك InnoDB، و `utf8mb4`. | بلا مفاتيح أجنبية يضعف D-01. نطلب قاعدة أخرى أو مزوّداً آخر. |
| A-05 | إصدار الإنتاج MySQL 8.0 أو MariaDB 10.6 أو أحدث. المحلي 10.4 للتطوير المبكر فقط. | إن كان الإنتاج 10.4 نبقى على مجموعة SQL المتوافقة ونخطط للترقية. |
| A-06 | يمكن وضع كود Laravel خارج `public_html`، وجذر الموقع يشير إلى مجلد `public`. | إن مُنع الوصول للمجلد الأب نستخدم التخطيط الاحتياطي الموثق في وثيقة النشر، مع حجب الملفات الحساسة بـ `.htaccess`. |
| A-07 | شهادة SSL من لوحة الاستضافة على النطاق الأساسي. | بلا SSL لا إطلاق. |
| A-08 | البريد عبر SMTP خارجي (مثل مزوّد معاملات) أو SMTP الاستضافة بعد اختبار التسليم. | روابط `wa.me` والواجهة تغطي التشغيل اليومي، لكن إعادة تعيين كلمة المرور تحتاج بريداً يعمل. |
| A-09 | حصة القرص الابتدائية 10 جيجابايت على الأقل، وInodes كافية لـ `vendor` والصور المضغوطة. | إن كانت الحصة أصغر تُنقل الصور إلى تخزين كائنات متوافق مع S3 من اليوم الأول. |
| A-10 | `memory_limit` للويب 256M كحد أدنى مقبول، و512M مستهدف. `max_execution_time` للويب 60. `upload_max_filesize` و `post_max_size` 8M على الأقل. | أقل من 128M يجعل Laravel غير مستقر. نطلب رفع الحد أو نغيّر المزوّد. |
| A-11 | الاتصالات الخارجية الصادرة HTTPS مسموحة نحو بوابة الدفع وSMTP. | إن كانت مغلقة لا دفع إلكتروني ولا بريد خارجي. |
| A-12 | المنطقة الزمنية التشغيلية الافتراضية `Africa/Cairo`. كل تواريخ العمل تُحفظ UTC وتُعرض بتوقيت المنشأة. | منشآت الخليج لاحقاً تضبط `timezone` على المنشأة. الإطلاق لا يفترض عدة مناطق داخل المنشأة الواحدة. |
| A-13 | المالك يقبل الفوترة اليدوية لأول المنشآت إذا تأخر عقد Paymob. | إن رُفض ذلك، بوابة الدفع تصبح على المسار الحرج للمرحلة 1. |

## 4. أسئلة لمزوّد الاستضافة

لا يبدأ نشر الإنتاج قبل إجابات مكتوبة. التطوير المحلي على XAMPP يمكن أن يبدأ بعد اعتماد هذه الخطة.

### 4.1 PHP

1. ما إصدار PHP المتاح لـ 8.2 و 8.3 و 8.4، وهل يمكن اختياره لكل نطاق؟
2. هل PHP CLI متاح؟ ما مساره الكامل؟
3. هل الدوال التالية معطلة في `disable_functions`: `proc_open`, `proc_get_status`, `symlink`, `exec`, `putenv`, `ini_set`؟
4. ما قيم `memory_limit` و `max_execution_time` و `max_input_time` و `post_max_size` و `upload_max_filesize` و `max_input_vars` و `max_file_uploads` للويب ولـ CLI؟
5. هل الامتدادات في A-01 مفعّلة، وهل WebP داخل GD مفعّل؟
6. هل OPcache مفعّل؟ هل يمكن مسحه بعد النشر بدون إعادة تشغيل الخادم بصلاحية root؟
7. هل `open_basedir` يقيّد الحساب بمجلد واحد؟ ما المسارات المسموحة؟

### 4.2 Cron وقاعدة البيانات

8. هل Cron متاح؟ ما أدنى تكرار (كل دقيقة أم كل 5 أو 15)؟
9. هل توجد مهلة قتل لأوامر Cron؟
10. ما إصدار MySQL أو MariaDB؟
11. كم قاعدة مسموحة؟ هل InnoDB والمفاتيح الأجنبية و `utf8mb4_unicode_ci` متاحة؟
12. هل يوجد حد اتصالات متزامنة أو حد حجم قاعدة؟
13. هل `event_scheduler` مفتوح؟ الخطة لا تحتاجه، والسؤال لمنع الاعتماد عليه بالخطأ.
14. هل النسخ الاحتياطي التلقائي (JetBackup أو ما يعادله) يومي، وما مدة الاحتفاظ، وهل الاسترجاع ذاتي من اللوحة؟

### 4.3 الملفات والنطاق والبريد

15. هل يمكن تغيير جذر الموقع إلى مجلد `public` داخل المشروع؟
16. هل `symlink` مسموح من PHP ومن cPanel؟
17. هل `.htaccess` يُحترم (Apache) أم يلزم قواعد LiteSpeed مكافئة؟ ما برنامج الخادم؟
18. ما حصة القرص والـ Inodes والنقل الشهري؟
19. هل SSL مجاني على النطاق وعلى `www`؟ هل Wildcard متاح وبأي تكلفة؟
20. هل النطاقات الفرعية غير المحدودة متاحة؟
21. هل SMTP الاستضافة يسلّم إلى Gmail وOutlook، أم المنفذ 587 مغلق؟
22. هل الاتصالات الصادرة إلى `accept.paymob.com` أو بوابة بديلة مسموحة؟
23. هل SSH للمستخدم (غير root) متاح أم اللوحة وFTP فقط؟
24. ما سياسة قتل العمليات الطويلة، وهل توجد حماية ModSecurity تكسر أجسام JSON لواجهة الطلب؟

### 4.4 حدود عملية يجب طلب أرقامها

| البند | الحد الأدنى المقبول للإطلاق | المستهدف |
|---|---|---|
| PHP | 8.3 | 8.4 |
| ذاكرة الويب | 256M | 512M |
| زمن تنفيذ الويب | 30 ثانية | 60 ثانية |
| زمن تنفيذ Cron | 60 ثانية | 120 ثانية |
| رفع الملفات | 8M | 16M |
| `max_input_vars` | 3000 | 5000 |
| قرص | 10 GB | 20 GB+ |
| Cron | كل دقيقة | كل دقيقة |
| قواعد البيانات | 1 بصلاحية DDL | 1 |
| SSL | إلزامي | إلزامي |

`max_input_vars=1000` في XAMPP المحلي منخفض لنماذج المعدّلات الكثيرة. على المحلي يجب رفعه لاحقاً عند التنفيذ، وعلى المزوّد نطلب 3000 على الأقل.

## 6. مجموعة SQL المسموحة

إلى أن يُؤكد إصدار الإنتاج ويُرقّى MariaDB المحلي فوق 10.4 عند الحاجة:

- InnoDB، `utf8mb4`، مفاتيح أجنبية مركبة، JSON كعمود تخزين لنسخ العنوان والقوالب.
- بلا فهارس وظيفية، بلا أعمدة مخفية، بلا اعتماد على `JSON_TABLE` في المسارات اليومية.
- القيود `CHECK` تُكتب فقط إذا أكد الإنتاج أنها تُفرَض. التحقق المالي يبقى أيضاً في طبقة Laravel حتى لا نثق بقيد يتجاهله إصدار قديم.
- لا إجراءات مخزنة إلزامية. التسلسل والدفتر في معاملات Eloquent حتى تبقى الهجرة قابلة للنقل.

## 7. ما لن نفعله في التخطيط الحالي

- لن نثبّت إصدارات الحزم بالأرقام الدقيقة قبل `composer create-project`. التثبيت خارج هذه المرحلة.
- لن نعد بزمن تشغيل 99.9٪ على استضافة مشتركة. الهدف الواقعي: تعافٍ من النسخة الاحتياطية خلال اليوم نفسه، وجدولة تتحمل تأخير Cron حتى 15 دقيقة.
- لن نعد بعمل نقطة البيع أثناء انقطاع الإنترنت في الإصدار الأول.
- لن نفتح منفذ WebSocket ولن نطلب VPS كشرط إطلاق.
