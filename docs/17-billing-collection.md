# 17 — التحصيل وويب هوك البوابة (P7-S17-08)

**الوضع الحالي (Q-03 / Q-04):** التحصيل اليدوي مقبول لأول المنشآت. لا عقد Paymob مفعّل في الإطلاق.

## المسار اليدوي المعتمد

1. المشرف يصدر فاتورة أو يستخدم الفاتورة المفتوحة.
2. يسجّل دفعة `manual` بمرجع بنكي فريد عبر شاشة المنشأة.
3. إعادة نفس `provider_ref` تُرفض (اختبار التكرار موجود).

## ويب هوك (جاهزية)

المسار: `POST /api/v1/webhooks/billing`  
- بلا جلسة CSRF.  
- يتطلب ترويسة `X-Restivo-Signature` = HMAC-SHA256 للجسم بمفتاح `BILLING_WEBHOOK_SECRET`.  
- توقيع خاطئ → 403 و**لا** تغيير لحالة الفاتورة.  
- توقيع صحيح مع `provider_ref` و`invoice_public_id` → يمر عبر `RecordPayment` بنفس قواعد عدم التكرار.

طالما `BILLING_WEBHOOK_SECRET` فارغ، المسار يرفض كل الطلبات (403) ويبقى التحصيل يدوياً فقط.
