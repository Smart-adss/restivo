**المشروع:** Restivo  
**المرحلة:** نهاية السبرنت 11 (المرحلة 4) + تصلب 17–18  
**المصدر:** `docs/13-testing-strategy.md` §8 وقبول السبرنت 11  
**توقيع محلي:** 18 نوفمبر 2026 (Africa/Cairo) — `php artisan test` = 129+ أخضر قبل إضافة اختبار الاستخدام

نفَّذ القائمة أولاً على بيئة محلية، ثم كرّرها على الاستضافة عند توفرها. علّم كل بند بعد التحقق.

## 1. آلية خضراء

- [x] `php artisan test` ناجح بالكامل على قاعدة الاختبار (sqlite :memory: في CI المحلي).
- [ ] الهجرة حتى آخر تهجير تُطبَّق بلا أخطاء على MySQL/MariaDB المستهدف — يُعاد على حساب المزوّد (Q-02).

## 2. سيناريو يدوي مكتوب → مثبت آلياً محلياً

1. [x] إنشاء منشأة من المنصة بخطة Growth — `TenancyIsolationTest` / `CreateTenant`.
2. [x] إنشاء تصنيف ومنتج بخيارات إجبارية وربطه بمحطة تحضير — `MenuCatalogTest` + `KitchenAndReportTest`.
3. [x] طلب من القائمة العامة؛ يظهر على لوحة الطلبات — `GuestOrderingTest` + `Sprint18PilotTest`.
4. [x] قبول الطلب؛ تُنشأ تذكرة مطبخ للمنتجات ذات المحطة فقط — `KitchenAndReportTest`.
5. [x] بيع كاشير مع وردية مفتوحة؛ التذكرة بلا أسعار ولا هواتف في الاستطلاع — `KitchenAndReportTest` + `PosSaleTest`.
6. [x] إغلاق الوردية بالمعدود المطابق للمتوقع — `PosSaleTest` + `Sprint18PilotTest`.
7. [x] تقرير يوم الفرع يطابق مجموع فواتير الاختبار — `KitchenAndReportTest::test_day_report_matches_known_sale_totals`.
8. [x] تشغيل `reports:fill-daily-summaries` مرتين؛ الأرقام لا تتضاعف — `KitchenAndReportTest::test_daily_summary_command_is_idempotent`.

## 3. مطبخ وتشغيل

- [x] منتج بلا `prep_station_id` لا ينشئ تذكرة — `KitchenAndReportTest`.
- [x] إيقاف Cron لا يمنع ظهور تذكرة لبيع جديد (التذاكر داخل معاملة البيع/القبول) — نفس مسار البيع/القبول في الاختبارات بلا عامل طابور للمطبخ.
- [x] البطاقة المتأخرة تعرض نص «متأخر» وليس تمييزاً لونياً فقط — `KitchenAndReportTest::test_late_ticket_is_labelled_with_text`.

## 4. أمن ونسخ

- [x] مشرف المنصة بمنصة TOTP مفعّل قبل أي عميل دافع (مسار `/platform/totp` جاهز؛ يُفعّل على حساب الإنتاج عند أول دخول).
- [ ] تجربة استعادة نسخة احتياطية موثّقة على حساب المزوّد — إجراء `docs/17-backup-restore-drill.md`.
- [x] منشأة تجريبية: سيناريو قبول آلي `Sprint18PilotTest` + إجراء ثلاثة أيام في `docs/18-pilot-runbook.md`؛ التنفيذ الحي عند توفر الاستضافة.

## 5. خارج نطاق الإطلاق التجاري

- المخزون والشراء والولاء والتقارير المتقدمة ليست شرطاً لهذا الإطلاق (موجودة كمراحل 5–6 ومغلقة بالميزات).

## ما يبقى قبل عميل دافع

1. مزوّد استضافة مجاب (Q-02) + عمود الإنتاج في `docs/17-hosting-provider-answers.md`.
2. نطاق (Q-01) + HTTPS.
3. تطبيق التهجير على MySQL الحي.
4. ثلاثة أيام تجريب حية + استعادة نسخة على حساب الاختبار.
5. تغيير كلمة بذرة المشرف + TOTP مؤكد على الإنتاج.
