# 20 — خطة تحويل واجهة Restivo (Premium SaaS UI/UX)

**التاريخ:** 18 نوفمبر 2026 (Africa/Cairo)  
**النطاق:** واجهة وتجربة استخدام فقط — بلا استضافة/نشر/بنية تحتية.  
**الاستثناءات التقنية:** لا كسر للمسارات، الصلاحيات، بوابات الميزات، العقود، أو منطق الأعمال. Blade + Tailwind 4 + JS الحالي (+ Alpine حيث يلزم). بدون Livewire كاعتماد للدخول (الدخول فورم عادي حالياً).

---

## 1) نتيجة المراجعة (Phase 1 — Audit)

### ما هو موجود فعلياً

| الطبقة | الواقع |
|---|---|
| التوكنات | في `resources/css/app.css` عبر `@theme`: canvas `#e7eeea`, ink/rail `#12201b`, brand `#145c40`, accent `#f2c14e`, line `#d5e0da`, danger `#9d2340` |
| الخطوط | IBM Plex Sans + Arabic مستضافة ذاتياً عبر `@fontsource` |
| المكوّنات | **لا يوجد** مجلد `components/` Blade مشترك — كل شاشة تكرر أصناف الأزرار/الحقول/الحدود |
| التخطيط | `layouts/app.blade.php` شريط جانبي داكن + رأس رقيق؛ قائمة طويلة مسطّحة بلا مجموعات |
| الأسطح التشغيلية | POS وKitchen داخل نفس `AppShell` (عكس وثيقة 11 التي توصي بسطح مركز بلا سايدبار) |
| القائمة العامة | تخطيط جوال `max-w-xl` نظيف نسبياً لكن بلا صور بارزة ولا تجربة طلب فاخرة |
| الحركة | شبه غائبة؛ لا `prefers-reduced-motion` |
| RTL | استخدام جيد غالباً لـ `border-s` / `text-start`؛ يحتاج تدقيق منهجي بعد توحيد المكوّنات |

### أدوار التجربة

1. **مشرف المنصة** — `/platform/*` (منشآت، خطط، دعم، تدقيق، مهام فاشلة، TOTP).  
2. **مالك/مدير المطعم** — `/app/*` مع صلاحيات وFeatureGate.  
3. **كاشير / مطبخ / صالة** — مسارات تشغيلية تحتاج سرعة ولمس.  
4. **ضيف** — قائمة عامة / طلب / حجز / تتبع.

### مشاكل جودة واضحة

1. **قائمة تنقل مسطّحة وطويلة** — عشرات الروابط بلا مجموعات (تشغيل / قائمة / مخزون / تقارير / إعدادات).  
2. **تكرار بصري «بطاقة بيضاء + حدود»** على معظم الشاشات → مظهر قالب موحّد.  
3. **لا Design System مكوّنات** — أزرار/حقول منسوخة يدوياً؛ اختلافات طفيفة في `rounded` و`min-h`.  
4. **الصفحة الرئيسية = قائمة فروع فقط** — ليست لوحة تشغيل «اليوم».  
5. **POS داخل الشِل العام** — عرض ضيق `max-w-5xl` يضر بسطح تابلت.  
6. **المطبخ داخل الشِل** — نفس المشكلة؛ التذاكر تحتاج مساحة وتباين أعلى.  
7. **لا PageHeader / Breadcrumb / EmptyState موحّد**.  
8. **الإشعارات** = فقرة `session('status')` بسيطة بلا طبقات نجاح/خطأ/تحذير متسقة.  
9. **المنصة والإدارة** نفس الـ shell دون تمييز بصري لهوية «SaaS تشغيل» مقابل «مطعم».  
10. **وثيقة 11** ما زالت تتحدث عن ألوان أقدم (`#F6F4EF` / accent terracota) بينما التنفيذ على هوية الغابة الخضراء — يجب مواءمة الوثيقة مع التنفيذ لاحقاً.

### ما لن نلمسه

- منطق البيع، الضرائب، المخزون، الاشتراكات، الويب هوك، الصلاحيات، الجداول.  
- مسارات API العامة.  
- إدخال مكتبات ثقيلة بلا حاجة (لا React rewrite، لا UI kit ضخم).

## 2) الاتجاه البصري

**الوعد:** برمجية SaaS مطاعم دولية هادئة — ثقة، وضوح تشغيل، كفاءة تحت الضغط.

**الهوية المعتمدة (مع تهذيب طفيف):**

| الرمز | القيمة | الاستعمال |
|---|---|---|
| `--color-ink` / rail | `#12201b` | نص وهوية الشريط |
| `--color-brand` | `#145c40` | إجراء أساسي |
| `--color-brand-ink` | `#f3faf6` | نص على الأخضر |
| `--color-accent` | `#f2c14e` | تمييز نشط / تنبيه غير خطر |
| `--color-canvas` | `#e7eeea` | خلفية التطبيق |
| `--color-surface` | `#ffffff` | أسطح المحتوى |
| `--color-line` | `#d5e0da` | حدود خفيفة |
| `--color-danger` | `#9d2340` | إلغاء / خطأ |
| `--color-success` | `#1f6b4a` (جديد، قريب من brand) | نجاح هادئ |
| `--color-muted` | ink @ 60–70% | نص ثانوي |

**قواعد ضد المظهر الـ AI:**

- لا تكرار بطاقة متطابقة في كل قسم.  
- لا تدرجات زخرفية ولا glassmorphism.  
- لا إيموجي كأيقونات واجهة.  
- أزرار متدرجة الأهمية (primary / secondary / ghost / danger).  
- POS والمطبخ والقائمة العامة لكل منها **نمط تخطيط مختلف** عن CRUD الإداري.

**الخط:** الإبقاء على IBM Plex Sans Arabic + Sans؛ أوزان 400/600 (+ 500 إن لزم للعناوين الثانوية). أرقام مالية: `tabular-nums`.

## 3) نظام التصميم (Foundation)

### مكوّنات Blade مشتركة (مقترح المسار)

`resources/views/components/ui/`

- `button`, `input`, `select`, `textarea`, `checkbox`  
- `page-header`, `section-title`  
- `panel` (سطح بحد خفيف — ليس إلزامياً لكل شيء)  
- `data-table` / صفوف قائمة  
- `status` (نص + لون، ليس pill مفرط)  
- `empty-state`, `alert`, `badge` (نادراً)  
- `modal` / تأكيد (Alpine خفيف)  
- `nav-group`, `nav-link`

### توكنات إضافية في `@theme`

- نصف قطر: `sm 6px` / `md 10px` / `lg 14px` — لا `rounded-full` للأزرار التشغيلية.  
- ظل: طبقة واحدة خفيفة للعناصر العائمة فقط (قوائم، مودال).  
- مسافات معيارية: 4 / 8 / 12 / 16 / 24 / 32.  
- انتقالات: `150–200ms` ease؛ احترام `prefers-reduced-motion`.

### تخطيطات

1. **`layouts/app`** — إدارة عامة (CRUD، تقارير، إعدادات).  
2. **`layouts/ops`** (جديد) — POS / مطبخ / صالة: بلا عمود تنقل ثقيل، رأس سياقي فقط.  
3. **`layouts/guest`** — دخول / TOTP.  
4. **`layouts/public`** (جديد أو تهذيب الحالية) — قائمة الضيف وطلب/حجز.

## 4) خطة التنفيذ بالمراحل

### المرحلة أ — الأساس (فرع أول قابل للمراجعة)

1. توسيع التوكنات في `app.css` + طبقات utility موحّدة.  
2. إنشاء مكوّنات `ui/*` واستبدال الاستعمال في الـ layout أولاً.  
3. إعادة هيكلة الشريط الجانبي إلى مجموعات (تشغيل / قائمة / مخزون / مالية / إعدادات) مع طي على الموبايل.  
4. رأس صفحة: عنوان + وصف قصير + إجراء أساسي واحد.  
5. تنبيهات `status` موحّدة.  
6. حركات خفيفة: hover للأزرار/الروابط، مؤشر نشط للناف، احترام reduced-motion.  
7. اختبار RTL/LTR على الـ shell.

**معيار قبول أ:** لا تغيير سلوك؛ الاختبارات الحالية خضراء؛ الشِل يبدو أكثر احترافية واتساقاً.

**حالة التنفيذ:** أ–ج مدمجة. المرحلة د على `cursor/ui-platform-public-a8b3` — تمييز وحدة المنصة، صفحات المنصة، TOTP على guest، `layouts/public`، قائمة ضيف بتصنيفات/صور/سلة، تتبع/حجز/طاولة.

### المرحلة ب — التشغيل الحرج

1. **POS** → `layouts/ops` بعرض كامل؛ شبكة منتجات أوضح؛ سلة ثابتة؛ أهداف لمس ≥44px؛ تغذية راجعة للإضافة/الكمية.  
2. **المطبخ** → سطح ops؛ تذاكر أعلى تبايناً؛ حالة «متأخر» نصية أوضح؛ انتقال حالة بسيط.  
3. **الصفحة الرئيسية للمالك** → نظرة تشغيل حقيقية من بيانات موجودة فقط (فروع، حالة اشتراك، روابط سريعة للمسارات المسموحة) — **بدون أرقام وهمية**.  
4. **المنتجات/التصنيفات** → جداول ونماذج عبر مكوّنات ui؛ معاينة صورة أوضح.

### المرحلة ج — بقية الوحدات

مخزون، مشتريات، صالة/حجوزات، تقارير، ضرائب، موظفين، فروع، اشتراك، دعم.

### المرحلة د — المنصة والضيف

1. منصة: تمييز بصري خفيف + جداول منشآت أوضح + استخدام ظاهر (موجود مسبقاً).  
2. دخول/TOTP بهوية العلامة.  
3. قائمة عامة: عرض منتجات أقوى (صور إن وُجدت)، تنقّل تصنيفات، سلة أوضح، جوال أولاً.

### المرحلة هـ — صقل وتحقق

- تدقيق كل الشاشات المعدّلة عربية/إنجليزية.  
- تابلت POS/مطبخ.  
- انحدار اختبارات Feature.  
- قائمة «متبقٍ بصرياً» صريحة إن بقي شيء خارج النطاق الزمني.

## 6) الحركة (مبادئ)

- CSS فقط في المرحلة أ–ب.  
- لا حركة تؤخر ضغط زر بيع أو تذكرة مطبخ.  
- `prefers-reduced-motion: reduce` يوقف التحريك غير الضروري.  
- لا مكتبات حركة مدفوعة/ثقيلة ما لم تُثبت حاجة بعد المرحلة ب.

---

## 7) التحقق بعد كل مرحلة

- `php artisan test` أخضر.  
- مراجعة يدوية `dir=rtl` و`ltr` على الشِل + الشاشة المعدّلة.  
- لا كسر لنماذج POST أو JS في `pos.js` / مطبخ poll.  
- الإبقاء على فحوصات الصلاحيات وFeatureGate كما هي في القوالب.
